# Catan

Everything Catan-specific lives here. Split by what it describes:

- `board.ts` — static structure for BOTH board variants. The top-level `HEXES`/`VERTICES`/`EDGES`/`adjacentVertices` + derived adjacency are the **standard** 19-hex board; `boardFor(variant)` returns a `Board` bundle (graph + resource/number/port config + layout natural-dims) for `'standard'` or `'expanded'`. `Hex`/`Vertex`/`Edge` are opaque `string`s (not literal unions) so both boards — whose ID namespaces overlap and differ in size — share one type; per-variant validity is enforced by the check scripts, not the compiler. Variant-aware code must resolve `boardFor(state.variant)` rather than importing the top-level standard constants. Each bundle also carries `spiralNumberSequence` — the fixed high/low token order for the `'spiral'` number layout (standard = authentic Catan A-R; expanded = tuned so reds never land adjacent), same multiset as `numbers`.
- `boardExpanded.ts` — GENERATED (by `dev/gen-expanded-board.ts`) geometry for the expanded 30-hex board (rows 3-4-5-6-5-4-3): `EXPANDED_HEXES/VERTICES/EDGES/adjacentVertices/COASTAL_EDGES/PORT_SLOTS`. Do not hand-edit; regenerate and paste. Same invariants as the standard board (adjacentVertices N-clockwise, EDGES sorted, COASTAL_EDGES a clockwise ring). Mirrored in the edge function.
- `types.ts` — `GameState`, `Phase`, sparse-storage helpers (`vertexStateOf`, `edgeStateOf`), and `GameConfig` (with `parseGameConfig` / `summarizeGameConfig` / `parseExtraBuild`). All persisted shapes. `GameConfig.extraBuild` (`ExtraBuildConfig`: `{ enabled, buildPhases: 'every' | 'across', moreThanSeven }`) configures the 5-6 player **special build phase**; the `special_build` Phase variant (`{ queue: number[] }`) drives it. `summarizeGameConfig` surfaces non-default extra-build settings only when `playerCount > 4`. `GameConfig.honk` (boolean, default `true`) is the per-game on/off for the Honk nudge — parsed defensively (a missing value defaults to enabled, so legacy rows keep honking), gated in `canHonk` and the edge `handleHonk`, and set by the create-game "Honking" toggle. `GameConfig.friendlyRobber` (boolean, default `false`) suppresses the robber during the first full go-around (`state.round < playerCount`): the gate lives **only** in the edge function's `applyRollOutcome` (server-authoritative — no pure-rules mirror), where a 7 in that window applies nomad desert production and returns to `main` (via `wrapMagicianWindow`) instead of entering the `discard`/`move_robber` chain — no discards, no move, no steal. Parsed defensively (missing → `false`, so legacy rows keep the standard robber) and set by the create-game "Friendly robber" toggle. `GameConfig.tradeMode` (`'automatic' | 'confirm'`, default/legacy `'automatic'`, parsed defensively) is the player-to-player trade acceptance mode — see `trade.ts`; set by the create-game "Trades" segmented control.
- `generate.ts` — fresh-game initialization: variant-keyed hex/port generation (reads counts/numbers/port composition from `boardFor(variant)`; the expanded board has 2 deserts, 28 tokens, and 11 ports = standard 9 + one 3:1 + one sheep 2:1), `initialGameState`, and `dealBonusHands`. `generateHexes(variant, layout)` places resources/deserts by shuffle either way; number tokens follow `config.numberLayout`: `'random'` shuffles the bag, `'spiral'` lays `board.spiralNumberSequence` along a spiral hex-walk (outer ring → center, from a random start corner + CW/CCW direction, skipping deserts) so 6s/8s spread out. The spiral geometry is derived from hex-ID row prefixes (kept identical to the edge mirror), not from `board.hexRows`. `NumberLayout` is on `GameConfig` (default `'spiral'`); the create-game "Random numbers" toggle flips it. (Resource/desert placement is always random.) (every player's `select_bonus` hand dealt in one pass, drawing bonuses/curses without replacement across the whole table; a hand's two offered bonuses are always distinct even when `config.bonusSets` filters the pool below `2 × playerCount`). Real games are dealt by the edge function's mirror of `dealBonusHands` — `initialGameState` is only reached from the `dev/` check scripts, so an edge deploy (`npm run edge`) is required for any deal-rules change to reach players.
- `placement.ts` — pure rules for the initial-placement phase (validity, target-settlement derivation, snake-order turn advance, starting-resource grant). No I/O; callable from UI helpers and tests.
- `roll.ts` — pure rules for the main-phase loop (dice roll, per-hex resource distribution, forward turn rotation). Also `acrossSeat` + `specialBuildQueue(eb, enderIdx, n)` — the special-build order after a turn ends (`across` = `[(ender + ⌊n/2⌋) % n]`; `every` = all others clockwise from `ender+1`; `[]` when disabled or ≤4 players). No I/O; callable from UI helpers and tests.
- `build.ts` — pure rules for main-phase builds (road, settlement, city): costs, affordability, validity (including the "no road through opponent settlement" rule). Also `handSize` and `canTakeSpecialBuildAction(state, idx)` (any build/buy/bank action available now, honoring `moreThanSeven`) used to auto-skip idle special-builders. No I/O; callable from UI helpers and tests.
- `trade.ts` — pure rules for player-to-player trade offers: shape validity, affordability, offer-addressing, hand swap, `rejectedByOf`/`acceptedByOf`. A game carries at most one open `TradeOffer` at a time. No I/O. **Trade mode** (`GameConfig.tradeMode`, `'automatic' | 'confirm'`, default/legacy `'automatic'`) governs acceptance: `'automatic'` swaps the moment an addressee accepts; `'confirm'` instead accumulates accepters in `TradeOffer.acceptedBy` (the offer stays open) and the proposer executes the swap with one of them via `confirm_trade`. Reject doubles as withdraw in confirm mode (drops the caller from `acceptedBy`). The actual swap always logs `trade_accepted` (on accept in automatic, on confirm in confirm) so ActionLog + `gameStats` are mode-agnostic; the interim acceptance logs an ephemeral `trade_accept_offered` (omitted from the log). The confirm-mode banner UI lives in `TradeBanner.tsx` (accepter chips for the proposer, a "Waiting…"/Withdraw state for an accepter), keyed purely off `acceptedBy` — empty in automatic mode, so no mode flag is threaded into the component.
- `ports.ts` — pure rules for ports (harbors) and bank trades: which port kinds a player has access to, which bank ratios they can use (2:1 specific / 3:1 generic / 4:1 default), shape validity for multi-group bank trades, hand update. No I/O.
- `robber.ts` — pure rules for the 7-roll chain: discard requirements, robber-movement validity, steal candidates. No I/O; callable from UI helpers and tests.
- `devCards.ts` — static dev-card data: `DevCardId` union, `DEV_CARD_POOL` (title/description/icon), `DEV_DECK_COMPOSITION` (classic 14/5/2/2/2 split). Mirror of `bonuses/`.
- `bonuses/` — static bonus + curse card data. `index.ts` defines shared types (`BonusId`, `CurseId`, `Bonus`, `Curse`) and re-exports. `bonuses.ts` has `BONUS_POOL`; `curses.ts` has `CURSE_POOL`. Both pools are mirrored in the edge function.
- `bonus.ts` — pure rules for sets 1, 2, and 3. Set 1: VP threshold (`winVPThresholdFor` takes both bonus + curse), port discount (`effectiveBankRatio`), underdog multiplier (`underdogMultiplierFor`), bricklayer alt cost (`bricklayerAltCost`, `BRICKLAYER_COST`), carpenter VP (`canBuyCarpenterVP`, `carpenterVPOf`), veteran knight tap (`availableKnightsToTap`, `canTapKnight`), gambler reroll (`canReroll`), aristocrat placement (`grantsStartingResourcesOnRound`), nomad d5 (`nomadResourceForRoll`). Set 2: populist VP (`populistBonusVPFor`, `pipCountFor`, `pipsAtVertex`), shepherd hand size (`shepherdEffectiveHandSize`, `canShepherdSwap`), ritualist (`isValidRitualTotal`, `ritualCardCost`, `dicePairForTotal`, `canRitualRoll`), fortune teller chain trigger (`fortuneTellerTriggersOn`), curio collector trigger (`curioCollectorTriggers`), metropolitan (`canBuildMoreSuperCities`, `superCityCount`, `metropolitanWheatSwapDelta`, `metropolitanCityCost`), forger (`forgerActive`, `canMoveForgerToken`, `hexesAdjacentTo`), scout (`isValidScoutSwap`, `scoutDevCardCost`, `scoutSwapOptions`/`affordableScoutSwaps`/`canScoutAffordDevCard` — a scout can pay the dev-card cost with a substituted resource, so buy-detection and the client cost picker gate on the affordable swap routes, not the standard cost), accountant (`roadLiquidationBlocked`, `ROAD_REFUND`/`SETTLEMENT_REFUND`/`CITY_REFUND`/`SUPER_CITY_REFUND`/`DEV_CARD_REFUND`). Set 3: plutocrat gain (`plutocratGain` — +50% on ≥2 of a resource, applied inside `distributeResources`), merchant add-on (`isValidMerchantAddon`, `singleGiveResource`, `MerchantAddon` — 1:1 side-conversion riding a bank trade), fencer (`FENCE_TOKEN_COUNT`, `fenceOwner`, `isFenceReservedAgainst`, `fenceRoadCost` — reserved edges in `GameState.fenceTokens`), smith brick↔ore (`smithCostOf`, `isValidSmithSwap`, `smithPortResourceOk` — fungible for builds/dev/ports), investor (`canInvest`, `investorTokenCount`, `investorPayout`, `INVESTOR_MAX_TOKENS`/`INVEST_TRIO`/`INVESTOR_ACTIVATE_VP` — gated at ≥3 VP, `PlayerState.investments`), magician (`isValidMagicTarget`, `magicDiscardCount` — post-roll phantom production), haunt (`resolveHauntGhosts`, `isGhost`, `HAUNT_SPOT_COUNT` — spawns 0-VP `'ghost'` buildings on blocked secret spots in `PlayerState.hauntSpots`). Singular filename (parallel to `dev.ts`) because `bonuses/` already owns the plural name.
- `dev.ts` — pure rules for development cards: cost, deck build + shuffle, buy/play validity, Largest Army recomputation, `totalVP` (including Longest Road +2 and hidden VP cards for self-views). No I/O.
- `longestRoad.ts` — pure rules for the Longest Road bonus: `longestRoadFor` walks an edge-disjoint trail per player (opponent buildings block pass-through at interior vertices); `recomputeLongestRoad` returns the new holder (≥5 trail, strict majority; ties keep current holder). No I/O.
- `honk.ts` — pure rules for the Honk nudge (`HONK_IDLE_MS` = 1 min, `lastActivityAt`, `honkTargetFor`, `honkersThisTurn`, `canHonk`). Derived entirely from `games.events` plus the per-game `config.honk` on/off flag — no other `GameState` field, no migration. `canHonk` takes an `enabled` arg (pass `gameState.config.honk !== false`, so legacy games with no stored value stay honkable); the edge `handleHonk` rejects with `config.honk === false`. `canHonk` gates the button in `MainLoopBar` / `SpecialBuildBar` and authorizes `handleHonk` server-side, so the two can't disagree; `now` is a parameter to keep it pure. Honkable in `roll`, `main`, and `special_build` only — the sub-phases (discard, robber, bonus picks) are already blocking prompts. Three rules are load-bearing and easy to break: **`honked` events are excluded from the idle clock** (counting them would let the first honker's ping restart the window and lock everyone else out, collapsing one-honk-per-sender into one-honk-total), **the per-turn window is everything after the last `turn_ended`** (which is what makes the allowance reset for free), and **the target comes from `honkTargetFor`, not `current_turn`** — during `special_build` the stalled player is `phase.queue[0]` while `current_turn` has already advanced to the next roller. The allowance is keyed per-target, since one turn window holds every special builder plus the roller. No I/O.
- `GameOverOverlay.tsx` — end-of-game modal shown when `games.status === 'complete'`, with three tabs: **Scores** (final scoreboard, reveals every player's hidden VP cards), **Rolls** (the shared 2–12 dice histogram), and **Highlights** (fun superlatives). Takes the full `events` log as a prop; the Rolls/Highlights tabs are pure derivations from it via `gameStats.ts`. Exports `FinalScoreButton` for the reopen affordance after dismiss.
- `gameStats.ts` — pure, client-only recap derivations over `games.events` (NOT mirrored in the edge function; no authority over state). `rollDistribution` counts shared `rolled` totals (bonus rolls excluded); `gameHighlights` computes the eight superlatives (Friendliest/Antisocial = most/fewest accepted player-to-player trades with both parties credited; Klutziest = cards discarded to 7s; Most Targeted = robber steals suffered; Biggest Honker/Honk-ee = honks sent/received; Speediest/Slowest = lowest/highest median whole-turn duration, where a turn spans the boundary that opens it — the prior `turn_ended`, or `placement_complete` for the first turn — to its own `turn_ended`). A highlight shows all seats tied for the extreme, or no winner when everybody ties (no standout) — which also covers the all-zero case for "most" awards.
- `gameContext.tsx` — React context that loads the per-game `games` row + `game_states` row and subscribes to realtime. Use `useGame()` in any subtree under `<GameProvider>`. Both rows are re-fetched and both channels re-subscribed on every app foreground (`useAppForeground`), because realtime events emitted while the app was backgrounded are never delivered. Both rows are also re-read whenever the viewer's own action succeeds (`lib/gameSync.ts`), so the board never depends on a channel to show the viewer a move they just made. Read `lib/stores/CLAUDE.md` before touching any of this — the rules there are load-bearing.
- `chatContext.tsx` — React context for the per-game chat thread (`game_messages`) plus the read cursor (`game_chat_reads`). Use `useChat()` under `<ChatProvider>`. Owes the same realtime debt as `gameContext.tsx` (`uniqueTopic`, refetch on `SUBSCRIBED`, resync on foreground, monotonic seq) — read `lib/stores/CLAUDE.md` first. The read cursor does double duty: it backs the unread badge **and** acts as a presence heartbeat (upserted every 15s while the panel is open) that the edge function reads to suppress a push for someone already looking at the thread. `CHAT_PRESENCE_MS` is mirrored in `game-service`; the heartbeat interval is deliberately half of it so one missed beat can't read as "away".
- `GameChat.tsx` — two exports, deliberately mounted at different levels of `app/game/[id].tsx`. `ChatButton` is the floating affordance with its unread badge, in the third slot below `BoardLegend` and `ActionLog` (`top: spacing.sm + 2 * (32 + spacing.xs)`), so it sits inside the board container with them. `ChatPanel` is the conversation, mounted at the play-area root (`bodyRoot`) so it covers the action bars but leaves the screen header clear — it is an absolutely-positioned view rather than a `Modal` **precisely so it stays inside the play area**; a `Modal` would cover the whole screen. Its top edge is measured from the buttons' line — a measured `topOffset` (the board container's `onLayout` y, which moves with the `PlayerStrip` / placement header) plus the shared `BUTTON_INSET` — then inset by `PANEL_GAP`. The keyboard is handled by a reanimated `useAnimatedKeyboard` `translateY` on the **scrim**, so the whole overlay moves as one translate, **not** `KeyboardAvoidingView`: the panel's bottom is pinned to the play area rather than the screen bottom, so padding-style avoidance leaves the composer under the keyboard. Translating alone would push the panel's top off screen, so once the lift exceeds the available `headroom` (the scrim's window y, measured via `measureInWindow` on layout, less `insets.top`) the panel takes the overflow as an animated `marginTop` instead — it is absolutely positioned against both the top and bottom of the scrim, so that shortens it rather than moving it, and its top parks at `insets.top + PANEL_GAP` (the same gap it keeps from its zone at rest). The measurement is skipped while the keyboard is up, since a layout pass then would read the translated position. Dismiss-on-outside-tap is an `absoluteFill` `Pressable` **behind** the panel, not a wrapper around it — the panel sits in a `pointerEvents="box-none"` wrapper inset by `PANEL_GAP - DISMISS_SLOP` that pads the difference back, so a transparent slop ring just inside the panel's visible edge falls through to the dismiss layer. Consecutive messages from one sender are grouped — only the run's first message shows the sender name and the `rowGroupStart` separation. That first message is the oldest in the run and thus the visual top of the run, so the separation from the run above is a `marginTop` (despite the `inverted` list). The panel is translucent (`PANEL_BG`, `colors.card` at 90%) over a light `0.15` scrim so the board stays faintly visible. Chat has **no rules layer**, so unlike the rest of this directory nothing here is mirrored into the edge function.
- `ResourceHand.tsx` — exports `ResourceHand` (the read-only full-size player hand) and the shared `CardFan` primitive it's built on (fanned/overlapping resource cards, solid|shadow variant, full|compact size, optional per-card tap + disabled set). Reuse `CardFan` for any fanned resource-card display rather than re-implementing the fan math; `TradePanel`'s give/receive composer is built from it.

## Constants are duplicated in the edge function

`supabase/functions/game-service/index.ts` re-declares `HEXES`, `VERTICES`, `EDGES`, `adjacentVertices`, the derived adjacency, **and the full expanded board + `BOARDS`/`boardFor`/`variantForPlayerCount` from `board.ts` + `boardExpanded.ts`** (server-side copy omits layout/coastal data it doesn't need), plus the placement rules from `placement.ts`, the hex-generation rules from `generate.ts` (including the spiral hex-walk + `*_SPIRAL_SEQUENCE` constants + `board.spiralNumberSequence`; `handleRespond` reads `config.numberLayout ?? 'spiral'`), the roll/distribution rules from `roll.ts`, the build rules from `build.ts`, the trade rules from `trade.ts` (including the `config.tradeMode` branch in `handleAcceptTrade`, `handleConfirmTrade` for the `confirm_trade` action, and the withdraw path in `handleRejectTrade`), the robber rules from `robber.ts`, the port/bank-trade rules from `ports.ts` (including `PORT_SLOTS` + `STANDARD_PORT_KINDS`), the dev-card rules from `dev.ts` + `devCards.ts` (deck composition, `DEV_CARD_COST`, `buildInitialDevDeck`, Largest Army recomputation), the Longest Road walk + recompute from `longestRoad.ts`, the honk rules from `honk.ts` (`HONK_IDLE_MS`, `lastActivityAt`, `honkersThisTurn`, `honkTargetFor` — inlined in `handleHonk` against loosely-typed `unknown[]` events, plus the `config.honk === false` gate mirroring `canHonk`'s `enabled` arg), and `totalVP` / `findWinner` (victory at 10 VP). The Deno bundler can't reliably import up-tree from `supabase/functions/`, so we accept a single redundancy: change both when rules or board data change. The source of truth is `lib/catan/`; the edge function is the copy. **The board variant is derived from player count** (`variantForPlayerCount`: 5-6 players → `'expanded'`, else `'standard'`) at game creation and persisted to `game_states.variant`; the client caps games at 6 players (`MAX_PLAYERS`).

Phase sub-phases (`discard`, `move_robber`, `steal`, `road_building`) carry a `resume: ResumePhase` pointer so effects triggered from different contexts return correctly: 7-roll chain resumes to `main`, knight played before rolling resumes to `roll`, road_building resumes to whichever phase the player was in.

**post_placement** sits between `initial_placement` and `roll`, for any start-of-game bonus that needs a player decision. It can carry `pending.specialist` (set-1 specialist), `pending.explorer` (set-2 explorer's 3 free roads), `pending.fencer` (set-3 fencer's 2 reserved-edge tokens), and `pending.haunt` (set-3 haunt's two secret spots). All drain in parallel — once every entry resolves, the phase advances to `roll`. Players without a start-of-game bonus don't block — the phase is skipped entirely when no pending entries exist. The edge function's `postPlacementPhaseFrom` helper rebuilds the pending after any one draining so a bonus resolving never wipes another's entries.

**Gambler roll confirmation**: for gambler players the `roll` phase carries `pending.dice` after the first roll. The player either commits (via `confirm_roll`, applying distribution / 7-chain) or rerolls once (via `reroll_dice`, setting `rerolledThisTurn`). Non-gambler rolls skip the pending state and apply atomically. Reset `rerolledThisTurn`, `boughtCarpenterVPThisTurn`, `ritualWasUsedThisTurn`, `shepherdUsedThisTurn`, `forgerMovedThisTurn` on `end_turn`.

**Set-2 sub-phases** chain via recursive `resume: Phase`:

- `scout_pick` — scout dev-card buy peek (top up-to-3); buyer picks one, the rest go to bottom of deck in drawn order. Resolved by `confirm_scout_card`.
- `curio_pick` — for any curio_collector who gained ≥1 card from a 2/12 original roll. Each pending entry independently claims +3 resources via `claim_curio`.
- `forger_pick` — head-of-queue forger picks one candidate to copy from for the token's hex on this roll, via `pick_forger_target`. Only entered when there are ≥2 eligible candidates; a single one is copied automatically during distribution (logged as the same `forger_copy` event).

A roll that triggers both curio AND forger chains as `forger_pick(resume = curio_pick(resume = main))`. Bonus rolls (fortune_teller) never trigger these or the robber. Forger token snap on a 7 fires inside `handleMoveRobber` (gated by `from7` flag carried through the `discard`/`move_robber`/`steal` chain).

**Set-3 sub-phase** — `magician_pick`: opens after the _magician's own_ roll fully resolves (distribution + any 7-chain). Wraps outermost (before curio/forger reactions) so the magician acts first — its phantom production doesn't affect their inputs. The magician either `cast_magic` (discard N+1 cards to also collect production as if a number N away had rolled — for themselves only, via `distributeResources(state, target)[roller]`) or `skip_magic`, then resumes. On a 7-chain the wrap is applied at the `move_robber`/`steal` → main transitions via `wrapMagicianWindow`; magician and fortune_teller are mutually exclusive by roller bonus. UI: only the magician gets a modal (`MagicianPickOverlay`) — everyone else sees a plain top status line in `app/game/[id].tsx`, never a blocking overlay. Same split as `post_placement`'s specialist, and for the same reason: a non-actor shouldn't have the board covered while they wait.

**Minimizable top-anchored overlays.** `MagicianPickOverlay` and `SpecialistDeclareOverlay` (in `PostPlacementOverlay.tsx`) share one pattern: a `Modal` with `backdropStyle` set to `justifyContent: 'flex-start'` + `paddingTop: insets.top`, a title row with a chevron that flips via `scaleY: 1 → -1`, and a body wrapped in an `Animated.View` that fades out while the sheet resizes through the Modal's `layout={LinearTransition}`. Top anchoring is what makes minimizing useful — the header holds position and the sheet shrinks upward, leaving the board visible. Copy this pair when a prompt needs to stay open while the player consults the board.

**Set-3 non-phase mechanics** — plutocrat/smith/merchant/fencer/investor are inline: plutocrat bumps summed roll gain in `distributeResources`; smith swaps the brick/ore cost component (`smith_swap` on build/buy actions, `isSmith` relaxes 2:1 specific ports in `isValidBankTradeShape`); merchant rides `bank_trade` via an optional `merchant` payload; fencer reserves edges in `GameState.fenceTokens` (new `fence_tokens` jsonb column — see migration) and pays 1 card on its own reserved edge (`fence_pay`); investor sets aside trios into `PlayerState.investments` (`invest` action) and is paid out at the start of its turn in `handleEndTurn`. The `'ghost'` VertexBuilding (haunt) is worth 0 VP, produces 1, is a steal target, and is transparent to the distance rule + longest-road + road-building for others (`isGhost` guards those checks); `settlementCountFor` excludes it, `totalVP` scores it 0.

**special_build** (5-6 player games, `config.extraBuild`) sits between a player's `end_turn` and the next `roll`. `handleEndTurn` advances `current_turn` and bumps `round` as usual but, instead of `roll`, writes `{ kind: 'special_build', queue }` when the queue is non-empty — `specialBuildQueue(eb, ender, N)` filtered through `drainSpecialBuildQueue` (drops leading players who `!canTakeSpecialBuildAction`). `queue[0]` is the acting builder (NOT `current_turn`); they may build road/settlement/city, buy a dev card, or bank/port trade — nothing else. `end_special_build` (`handleEndSpecialBuild`) pops the head, re-drains, and either continues with the next builder or falls through to `roll` for the already-advanced `current_turn`. The acting builder is gated by `isSpecialBuildActor` (queue head + `moreThanSeven` hand check); the four build/buy/bank handlers accept it in addition to `main` (`preflightBuild(…, allowSpecialBuild=true)` for settlement/city; inline branches in `handleBuildRoad` / `handleBankTrade` / `handleBuyDevCard`). Super-city, carpenter-VP, tap-knight, liquidate, dev-card play, robber, roll, and player-trade stay `main` + `current_turn` only. Age-curse `cardsSpentThisTurn` accumulated during a builder's SBP slot is NOT reset when the slot ends — it carries forward and counts toward the card limit of the builder's own following turn (the counter is cleared only on their `end_turn`). **Known limitation:** a `scout` may not buy a dev card during the SBP (its peek `scout_pick.resume` can't hold the build queue) — server rejects it, client disables the button. Notifications reuse `your_turn`. Legacy games with no `config.extraBuild` default to disabled (never disrupted). Fully mirrored in the edge function.

Note the two set-3 build interactions must both honour the special build phase: `handleBuildRoad`'s fencer-reserved-edge discount and smith `smith_swap` (and `handleBuyDevCard`/`handleBankTrade`'s smith/merchant paths) already run inside the same handlers the SBP reuses, so they work in either phase.

**placedTurn** (required field on occupied vertices and edges) records `state.round` at placement time. Initial-placement pieces stamp `placedTurn = 0`. Used by the accountant's liquidation gate (`placedTurn < state.round`) to enforce "not the same turn it was bought".

`dev/check-catan-board.ts` validates BOTH variants (counts, adjacency, coastal ring, port spacing, resource/number/port composition); `dev/gen-expanded-board.ts` regenerates the expanded geometry for `boardExpanded.ts` (run it, paste output into `boardExpanded.ts` and the edge-function mirror). When in doubt, run the check scripts — `npx tsx dev/check-catan-board.ts`, `check-catan-placement.ts`, `check-catan-roll.ts`, `check-catan-build.ts`, `check-catan-trade.ts`, `check-catan-robber.ts`, `check-catan-ports.ts`, `check-catan-dev.ts`, `check-catan-longest-road.ts`, `check-catan-curses.ts`, `check-catan-bonuses.ts`, `check-catan-honk.ts` — after edits. The edge function is only validated at deploy time (`npm run edge`).

## Sparse storage

`GameState.vertices` and `GameState.edges` are `Partial<Record<…, …>>`. Missing keys default to `{ occupied: false }` via `vertexStateOf` / `edgeStateOf`. Code that writes state should continue to set only occupied entries — never pre-fill 54 + 72 empty entries.
