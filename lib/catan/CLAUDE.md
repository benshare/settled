# Catan

Everything Catan-specific lives here. The rules files (`*.ts`) are pure, no I/O, callable from UI and the `dev/check-*.ts` scripts. **Almost all of them are mirrored in the edge function** — see the "Constants are duplicated in the edge function" section; that mirror is the authority for real games, so a rules change needs an edge deploy (`npm run edge`) to reach players.

## Board and static data

- `board.ts` — static structure for both board variants. Top-level `HEXES`/`VERTICES`/`EDGES`/adjacency are the **standard** 19-hex board; `boardFor(variant)` returns a `Board` bundle (graph + resource/number/port config + layout dims) for `'standard'` or `'expanded'`. `Hex`/`Vertex`/`Edge` are opaque `string`s (not literal unions) so both boards share one type; per-variant validity is enforced by the check scripts, not the compiler. **Variant-aware code must resolve `boardFor(state.variant)`, never the top-level standard constants.** Each bundle also carries `spiralNumberSequence`, the fixed token order for the `'spiral'` number layout.
- `boardExpanded.ts` — **generated** by `dev/gen-expanded-board.ts`; do not hand-edit. Regenerate and paste (into here and the edge mirror).
- `colors.ts` — pure rules for player colors. `COLOR_IDS[seat]` is the **pre-preferences convention** (the color a seat used to get by definition), which is what makes the settings screen's opening arrangement and the `games.colors` backfill one-liners. `resolveColorPreferences(prefs, rng)` walks every seat's ranking a depth at a time; `rng` is injectable so the check script can assert exact outcomes. **`parseColorPrefs` deliberately does not pad**: an empty `color_prefs` means _no preference_ and resolves at random, NOT to the default order. The resolve actually runs only in the edge function's `handleRespond`. See Player colors below.
- `types.ts` — `GameState`, `Phase`, sparse-storage helpers, and `GameConfig`. See the GameConfig section below.
- `generate.ts` — fresh-game initialization: variant-keyed hex/port generation, `initialGameState`, and `dealBonusHands`. Number tokens follow `config.numberLayout` (`'random'` shuffles; `'spiral'` lays `spiralNumberSequence` along a hex-walk so 6s/8s spread out); resource/desert placement is always random. `dealBonusHands` draws every player's `select_bonus` hand in one pass without replacement across the whole table, honoring `bonusSets` / `bannedCombos` / per-`GameSize` availability via `pickPool`'s widening fallback (set ∩ available → available → full pool), so a filter can narrow a deal but never break it. Cross-table uniqueness degrades only where the pool runs out (6 players × 3 curses > the 11-card pool). Real deals run in the edge mirror; `initialGameState` is reached only from the check scripts.
- `placement.ts` — pure rules for initial placement (validity, target-settlement derivation, snake-order advance, starting-resource grant), plus the **drafted-turn** helpers (`applyPlacementDraft`, `placementPairsExpected`) and the **`pick_last`** helpers (`isDoublePlacementSeat`, `swapPlacementPairs`). See the initial-placement notes below.
- `roll.ts` — pure rules for the main-phase loop. `gainsFromHex(state, hex, total)` is the one-hex, **robber-blind** slice the forger copies through — anything that needs "what would this hex pay" regardless of the robber must go through it, since the per-hex map has already dropped the blocked hex. Also `specialBuildQueue`, the special-build order after a turn ends.
- `build.ts` — pure rules for main-phase builds. **Road affordability is not a single boolean**: `payableBuildRoadEdges` narrows `validBuildRoadEdges` to what the hand can cover, which for a fencer holding only one of Wood/Brick is just their own reserved edges. The road button, the board's pulse layer, and both `canTakeSpecialBuildAction` mirrors gate on that set, not on `canAffordPurchase('road')`. Free roads (explorer, Road Building) stay on the unnarrowed set.
- `trade.ts` — pure rules for player-to-player trades. At most one open `TradeOffer` at a time. **Trade mode** (`GameConfig.tradeMode`) governs acceptance: `'automatic'` swaps the moment an addressee accepts; `'confirm'` accumulates accepters in `acceptedBy` and the proposer executes via `confirm_trade` (reject doubles as withdraw). The swap always logs `trade_accepted` so ActionLog + `gameStats` are mode-agnostic. Confirm-mode banner UI is `TradeBanner.tsx`, keyed purely off `acceptedBy`.
- `ports.ts` — pure rules for ports and bank trades. A bank trade is **not** priced at one chosen ratio — see the bank-combination section; `bankPartitionFor` is the validity test both client and server gate on. The older per-kind helpers survive here as primitives for the rate hint but have no server mirror.
- `robber.ts` — pure rules for the 7-roll chain. `isForcedFullDiscard` flags a required count equal to the whole hand (only the `avarice` curse produces it); the edge's `applyForcedDiscards` takes those hands itself inside `applyRollOutcome` so a player never sees a prompt with no decision, and a table where the cursed player was the only one over the limit skips the `discard` phase entirely.
- `devCards.ts` / `bonuses/` — static card data (dev cards; bonus + curse pools, `combos.ts` pairings, `sizes.ts` per-player-count deviations). All mirrored in the edge function.
- `bonus.ts` — pure rules for bonus/curse sets 1–3, one helper group per card. Singular filename (parallel to `dev.ts`) because `bonuses/` owns the plural.
- `dev.ts` — pure rules for development cards (cost, deck build/shuffle, buy/play validity, Largest Army, `totalVP` including Longest Road +2 and hidden VP cards).
- `longestRoad.ts` — pure rules for the Longest Road bonus (edge-disjoint trail per player, opponent buildings block pass-through; ≥5 and strict majority, ties keep current holder).
- `honk.ts` — pure rules for the Honk nudge. Derived entirely from `games.events` + the per-game `config.honk` flag. Three rules are load-bearing and easy to break: **`honked` events are excluded from the idle clock** (else the first honker's ping restarts the window and locks everyone else out); **the per-turn window is everything after the last `turn_ended`** (which resets the allowance for free); and **the target comes from `honkTargetFor`, not `current_turn`** (during `special_build` the stalled player is `phase.queue[0]`). The allowance is keyed per-target. `canHonk` gates both the button and the server's `handleHonk`, so they can't disagree.
- `timeout.ts` — pure rules for move timeouts (see the Move timeouts section). Mirrored in the edge function, which owns writing `games.deadline_at` and acting on it. The ticking half is `useCountdown.ts`, kept out of here so this file stays a pure mirror.
- `useCountdown.ts` — the one React hook turning `games.deadline_at` into a live remaining-time number; returns `null` until the deadline is within `COUNTDOWN_VISIBLE_MS` (an hour), so a 7-day game runs no interval for most of its life. **Mount it once per surface, not once per seat.**

## UI components

The board and screen assembly are described in `lib/game/CLAUDE.md`; this directory holds the Catan-specific pieces. Chat has **no rules layer**, so unlike the rest of this directory nothing in `chatContext`/`GameChat` is mirrored into the edge function. Component internals (layout math, exact copy) are left to the code — the notes here are the cross-component contracts.

- `gameContext.tsx` — React context for one game; use `useGame()` under `<GameProvider>`. The exposed `gameState` is a **join of two rows** (`game_states` supplies the board; `games` supplies `config`/`colors`), so it stays `undefined` until both land. It owns the `games` row (fetch + realtime) but **not the board**: that comes from `useGameStatesStore`, which already holds every game the viewer is seated at, so opening one renders warm rather than loading. The provider registers the game on screen with `watch`/`unwatch`, which is what covers a spectated or finished game. Also exposes `isSpectator` and `watcherIds` — read both from here, never re-derive, so the board and chat can't disagree. `watcherIds` comes from an ephemeral Supabase Presence channel (`watchers:<gameId>`) where only spectators `track()`. Both channels owe the realtime debts in `lib/stores/CLAUDE.md` (`uniqueTopic`, resync on foreground, refetch from `SUBSCRIBED`) and **never apply a realtime payload wholesale** (`isPartialGameRow`). The provider is not remounted on a header tab switch, so it clears its per-game state on a `gameId` change. **Read `lib/stores/CLAUDE.md` before touching any of this.**
- `chatContext.tsx` — React context for the per-game chat thread + read cursor; use `useChat()` under `<ChatProvider>`. Owes the same realtime debts as `gameContext`. The read cursor does double duty: unread badge **and** a presence heartbeat (`CHAT_PRESENCE_MS`, mirrored in the edge function) that suppresses a push for someone already looking. It also owns the **typing indicator** (`typingIds`/`noteTyping`), backed by a second ephemeral Presence channel joined only while the panel is open — membership _is_ the signal (the viewer `track()`s rather than tracking a flag), and `track` is re-asserted from the `SUBSCRIBED` callback so a reconnect mid-sentence survives. See `.claude/specs/chat-typing-indicator.md`.
- `palette.ts` — the physical-game palette plus `seatColor(state, seat)` / `seatColors(state)`. **`playerColors` is keyed by `ColorId`, not seat index** — never index it with a seat number; go through `seatColor`. See Player colors.
- `ActionLog.tsx` — the floating log panel; read-only formatting of `games.events` via `describeEvent`, plus a filter chip row. **A new event kind added to the edge function must also be added to the `GameEvent` union in `lib/stores/useGamesStore.ts`**, or it's written server-side and never appears in anyone's log (`describeEvent`'s `default` swallows unknowns). Roll expansion needs server help: `applyRollOutcome` hangs a per-seat `gains` map off the roll event, optional so old rolls read as un-expandable rather than claiming nobody collected. The `stolen` event carries `resource` the same way (optional, same legacy reason), but the row expands **only for the thief and the victim** — for everyone else it stays a flat line, the same secrecy the steal animation already keeps. Passive bonuses with no discrete moment (plutocrat/underdog/etc.) are deliberately unlogged.
- `GameOverOverlay.tsx` — end-of-game modal (Scores / Rolls / Highlights tabs), shown when the game is finished; the Rolls/Highlights tabs are pure derivations from `events` via `gameStats.ts`. **Rematch** is an optional `onRematch` supplied by `app/game/[id].tsx` (omitted for a spectator), routing to `/create-game` seeded with this game's config.
- `gameStats.ts` — pure, client-only recap derivations over `games.events` (NOT mirrored server-side, no authority). A highlight shows all seats tied for the extreme, or no winner when everybody ties.
- The remaining game-screen surfaces (`GameChat`, `GameTitle`, `switchableGames`, `TradePanel`, `DiscardPanel`, `ResourceHand`, `Watchers`) — the load-bearing cross-cutting rules:
    - **`ChatPanel` is an absolutely-positioned view, not a `<Modal>`** — it fills its layout's own container (safe-area top + a gap, down to the bottom of the dock / action bar), so the layout's chrome can react to it (both top bars fade under it) and the board stays faintly visible through it. **Its top never moves**: only the bottom edge tracks the keyboard, stopping a gap above it, so the conversation shortens instead of sliding. `ChatButton` and `ChatPanel` are two exports mounted at different levels (see `lib/game/CLAUDE.md`).
    - **`GameTitle`'s tab strip navigates with `router.setParams`, never `router.replace`** — `REPLACE` remounts the whole game screen (providers included) on every tab tap. A tab whose game is waiting on the viewer carries an accent dot from the shared `isMyTurn`, which is `pendingUserIds` over that game's phase (see Move timeouts) — the same signal as the Games list dot and the app-icon badge.
    - **`switchableGames.ts`** (`useSwitchableGames()`) is the ordered tab set — active games plus the _actively-spectated_ in-progress subset — shared by `GameTitle` and the game screen's zone sliders so the strip's order and the slide's direction can't disagree.
    - **`TradePanel` is one composer with two destinations** (propose to players / trade with the bank), not a flow: the same give/receive pair feeds both, the bank button enables exactly when `bankPartitionFor` can pay, and there is no ratio picker. It and `DiscardPanel` **replace the viewer's hand** (rather than being a bar of their own) because each is composed by tapping the hand; both are built on `ResourceHand`'s shared `CardFan` primitive — reuse it for any fanned resource-card display.
    - **`ResourceHand` is the only surface that renders `displayHand`** (the reveal-animation hold); everything else reads the live hand. See `lib/game/CLAUDE.md`.
    - **`Watchers.tsx`** floats a watcher-count button and a spectator-only stop-watching button; both call `ensureProfiles` since a watcher may be someone the viewer has never met.

## GameConfig (immutable per-game metadata)

`GameConfig` is persisted on **`games.config`, not on the `game_states` row** — it is immutable, written once at creation, and the spectator RLS policies need to read it from the `games` row. `gameState.config` is therefore assembled in `gameContext.tsx` by joining the two rows, and `BoardState` is `Omit<GameState, 'config' | 'colors'>`. Every field is **parsed defensively** (`config` is unvalidated JSON), so a missing value falls back to a default and legacy rows keep working. Two things are worth knowing beyond that:

- **`timeout` is the one field that does NOT fall back to `DEFAULT_CONFIG`** — an unrecognized/missing value reads as `null` (no clock), because a stored row records the clock a game was actually played under and moving the default must not rewrite it. In-flight games when the default moved were backfilled by migration instead.
- **A handful of settings are enforced server-authoritatively, with no pure-rules mirror** — the gate lives _only_ in the edge function: `friendlyRobber` (suppresses the robber during the first go-around, in `applyRollOutcome`), `limitMonopoly` (caps a single opponent's Monopoly loss at `monopolyCap`, in `handlePlayDevCard`). Everything else (`honk`, `tradeMode`, `bonusCount`/`curseCount`, `spectators`, `numberLayout`, `extraBuild`) has a normal mirror. `bonusCount`/`curseCount` at 1 each **skips the selection phase entirely** (`needsBonusSelection`).

`GameState.undo`, `GameState.colors`, and `GameSize`/`gameSizeFor` also live in `types.ts` — see the Undo, Player colors, and Game size sections.

## Bank trades combine rates

A bank trade is **not** priced at one chosen ratio. The give is cut into groups — each a whole number of cards of one resource at one of that resource's available rates — and the number of groups is the number of cards received. So a 2:1 wheat port and the 4:1 bank combine: 2 wheat + 4 wood buys 2 cards. `bankPartitionFor(state, idx, give, receive)` (`ports.ts`) is the whole rule, and a **non-null return is both the validity answer and the record of what was charged** — the client gates the button on it, the server logs the partition. See `.claude/specs/trade-refactor.md`.

- **`bankRatesFor` owns which rates apply.** 4:1 always, 3:1 with a generic port, 2:1 with the specific port (or a smith's brick/ore counterpart). Provinciality rewrites the whole map. The specialist discount applies only when the whole give is a single stack of the declared resource.
- **Reachability is a DP, not arithmetic.** A rate set has holes ({2,4} can't make an odd pile), so a min/max range check would wave invalid trades through. Hands are tiny; the cost is nothing.
- **The merchant's 1:1 extras are ordinary groups now** — a ratio-1 rate usable only alongside a full-price group. No `merchant` payload on the action anymore; the edge still folds a legacy one in before validating.
- **`ratio` on the `bank_trade` event is optional** (written only when the partition was uniform); `rates` carries the breakdown either way.

## Game size (bonus / curse variants by player count)

`GameSize` (`types.ts`) is `'small'` (2p) / `'standard'` (3–4p) / `'expanded'` (5–6p), derived by `gameSizeFor(playerCount)` and **never persisted** — deliberately separate from `Variant`, since a card can vary at 2 players where the board doesn't.

- **`gameSizeFor` has a third mirror in SQL.** The `card_stats` view (`.claude/specs/card-global-stats.md`) buckets `game_results.player_count` the same way, which is what the catalog's size filter checks off (`.claude/specs/card-stats-filter.md`). Retuning the boundaries means a migration too. The catalog's card **text**, unlike its numbers, is always the `standard` baseline — the filter is a lens on the sample, not a mode the card is read in.
- **`bonuses/sizes.ts` is the one location for the deviations.** `BONUS_SIZE_VARIANTS` / `CURSE_SIZE_VARIANTS` are keyed card id → size → params; `BONUS_POOL`/`CURSE_POOL` stay the `standard` baseline and the fallback, so a card that doesn't vary needs no entry (32 of 38 have none). Full table in `.claude/specs/bonus-size-variants.md`.
- **Retuning a card is two edits**: its entry in `sizes.ts`, and a `switch (size)` in that card's rule helper. Params are typed per card (`BonusSizeParams`/`CurseSizeParams`) so a param on the wrong card fails to compile.
- **Never read `.description` off a pool entry where a player count is known** — use `bonusDescriptionFor` / `curseDescriptionFor`. **`available: false` gates the DEAL only** — a card someone already holds still resolves a description at every size, so a game in flight can never render blank.
- **A variant that isn't just a number needs its own machinery**, and two do: provinciality (priced into the ratio via `bankSurchargeFor`, or an empty `availableBankOptions` the UI reads to disable the bank) and the gambler's expanded second pair in `phase.pending.altDice`.
- **The magician declares no variants** — flat N + 1, no cooldown, every size. Its `discardPlus` / `cooldown` params and the reads of them (`magicDiscardCount`, `magicianCanCast`) survive unset, as does `PlayerState.lastMagicRound`, which is still stamped on cast. Retuning it is a `sizes.ts` edit alone.

## Undo (one step)

A player may take back their own last action when it was **solo and information-free** — `UNDOABLE_ACTIONS` in `types.ts`, mirrored in the edge function (the authority). Rolling, buying/playing a dev card, and every multi-player trade are excluded on principle: taking those reveals something. Three load-bearing points:

- **It restores a snapshot, it does not compute an inverse.** The edge dispatcher stashes the pre-action `game_states` row on `game_states.undo` (jsonb) and `handleUndo` writes it back. A single road build can move Longest Road, consume a fence token, apply a cost substitution, and bump the age curse's counter — an inverse would rot the first time one bonus was missed.
- **The snapshot is maintained in `serve`, not the handlers.** An action opts in by joining `UNDOABLE_ACTIONS` and doing nothing else; every other action clears the column on success. `send_message` is the sole exemption (chat writes neither table); `honk` is deliberately _not_ exempt (it appends to `games.events`, which undo truncates by length).
- **Undo truncates `games.events` back to its pre-action length**, so the undone action vanishes from `ActionLog` rather than being annotated.

`GameState.undo` is what the client reads to show the arrow — never a derivation from the log. Only the acting seat may undo; a game-winning action can't be undone. The arrow follows the floor-holder, which during `special_build` is `phase.queue[0]`. Full design in `.claude/specs/undo.md`.

## Forfeiting and ending

Two withdrawable, per-player declarations that a game can end without anyone reaching the VP threshold. Both are plain user-id arrays on the **games** row (`forfeits`, `end_votes`), written only by the edge function. Full design in `.claude/specs/forfeit-and-end-game.md`.

- **Forfeit**: when every seat but one holds a standing forfeit, that survivor wins **regardless of VP** (`status = 'complete'`, `by_forfeit: true`; `findWinner` is not consulted).
- **End game**: needs the whole table; the last vote sets `status = 'canceled'`, `winner` null, and writes `game_canceled` (deliberately not `game_complete` — no winner, no scoreboard).

The rule that keeps this small: **neither declaration has any mechanical effect while it stands.** Nothing in the turn engine, robber chain, trade rules, discard, queue or scoring reads either array — only the two thresholds do. Skipping a forfeiter in turn order instead would put a new condition into every turn-advance, steal-target, trade-addressee and discard path. Consequences:

- **`isFinished(status)` is the status test, not `=== 'complete'`** (a canceled game shares History and the "board accepts nothing" posture).
- **Stats treat the two endings differently**: a canceled game writes no `game_results` rows; a forfeited one writes them with `forfeit: true` and counts toward games played and win rate only.

`GameOverOverlay` takes both as optional props; `PlayerStrip` flags a forfeited seat (a flag, not a dimmed card — the seat is still playing). The affordance is `lib/game/GameMenu.tsx`.

## Move timeouts

A per-game clock (`GameConfig.timeout`, default `'2d'`; `null` = off) that skips whoever is holding the game up. Rules in `timeout.ts`, enforcement entirely in the edge function. Full design in `.claude/specs/move-timeouts.md`.

- **The clock is the game's, not a player's.** `games.deadline_at` is stamped after every action by anyone, so a table that is visibly playing never times out (the same idle model as Honk; honks and chat are excluded for the same reason).
- **`pendingSeats(phase, currentTurn)` is who the clock is on** — never `current_turn`, which names the wrong seat during `special_build` and is null through bonus selection. It's an exhaustive `switch`, so a new phase fails to compile rather than becoming un-timeout-able. **`pendingUserIds` is the same rule in user ids**, and it backs more than the clock: the Games list dot, the header tab badge and the app-icon badge all read it (via `isMyTurn`), which is why the client caches every active game's phase in `useGameStatesStore`. The server copy is `supabase/functions/_shared/phase.ts`, shared by the timeout sweep and `_notify`'s badge count.
- **Two players: running out of time is losing** — the seat joins `games.forfeits` and the game completes through the ordinary forfeit path (both idle → cancel).
- **Three or more: the seat is skipped, and the skip is a real action** — the sweep picks an arbitrary legal choice and calls the ordinary handler via `dispatch`, so `ActionLog` shows a normal roll/discard/end turn. There are no timeout event kinds.
- **A skipped seat's next window is one minute** (`TIMEOUT_PENALTY_MS`, `games.timed_out`) until it acts again, or an absent player would stall the table for a fresh full window every go-around.

## Player colors

Which color a player gets is **data on the game** (`games.colors`, one `ColorId` per seat), resolved once at creation, not a derivation from seat order. Rules in `colors.ts`; the resolve runs only in the edge's `handleRespond`. See `.claude/specs/color-preferences.md`.

- **Never index the palette by seat** — `playerColors` is keyed by `ColorId`. Use `seatColor(state, i)` where you hold a `GameState`, take a `seatColors` prop where you don't. The split is deliberate: state-holders resolve it themselves; leaf SVG pieces take a `color: string`; presentational components are prop-drilled from `useGame().seatColors` (one derivation, so board and log can't disagree).
- **An empty ranking means random, not default** — `parseColorPrefs` refusing to pad is what enforces the behavior change from the old seat-index convention.
- **Preferences are read at game start, not invite time** (a request can sit pending for days); a failed profile read falls back to "no preference" rather than blocking the game. Games created before this shipped were backfilled with `COLOR_IDS[seat]`.

## Constants are duplicated in the edge function

`supabase/functions/game-service/index.ts` re-declares essentially all of the board data and rules files above (board graph + expanded board + `boardFor`, placement, generation, roll/distribution, build, trade, robber, ports' combination layer, dev cards, Longest Road, honk, `UNDOABLE_ACTIONS`, colors, `gameSizeFor` + the size-variant availability flags, and `totalVP`/`findWinner`). The Deno bundler can't reliably import up-tree from `supabase/functions/`, so we accept a single redundancy: **`lib/catan/` is the source of truth; the edge function is the copy; change both when rules or board data change.** Only the layers the server actually runs are mirrored — the per-kind bank helpers, description resolvers, and the client-only `parseGameColors`/injectable `rng` have no server caller and are deliberately not copied. The board variant is derived from player count (`variantForPlayerCount`: 5–6 → `'expanded'`) at creation and persisted to `game_states.variant`.

### Phases and sub-phases

Sub-phases (`discard`, `move_robber`, `steal`, `road_building`) carry a `resume: ResumePhase` pointer so an effect returns to wherever it was triggered from.

- **`GameState.currentTurn` is `null` for the whole `select_bonus` phase** (picks are parallel, no seat holds the turn). Anything reading it must tolerate `null` — and must not mistake it for "who is the game waiting on", which is `pendingSeats`. It lives on `game_states` beside `phase` because it is progress, not identity; `games.current_turn` survives as a write-only mirror for clients predating the move and is dropped in release 2 (`.claude/specs/current-turn-on-game-states.md`).
- **A placement turn is chosen locally and submitted whole** (`place_start`): one settlement+road pair — or two for seat `N-1` — validated pair-by-pair. Consequences: `phase.step` stays `'settlement'` for the whole turn (the stage is local device state), taking a piece back is free (nothing sent), and other clients see the settlement and road appear together. See `.claude/specs/combined-placement-step.md`.
- **`pick_last`** is the one place the snake order pauses mid-round: seat `N-1` places both starting settlements back-to-back, then nominates one via `choose_last_settlement` to pay the starting resources (deferred by `placeSettlementPiece`). The nomination rewrites the log via `swapPlacementPairs`. Skipped for an aristocrat (collects on both). See `.claude/specs/last-settlement-choice.md`.
- **`post_placement`** sits between placement and `roll` for any start-of-game bonus needing a decision (specialist, explorer, fencer, haunt); all pending entries drain in parallel and the phase is skipped when none exist.
- **Gambler roll confirmation**: the `roll` phase carries `pending.dice` after a gambler's first roll — commit via `confirm_roll` or reroll once via `reroll_dice`. Non-gambler rolls apply atomically.
- **Set-2 sub-phases** chain via recursive `resume: Phase`: `scout_pick` (dev-card buy peek — not entered on the deck's last card, a decision-free prompt), `curio_pick` (+3 resources per curio_collector on a 2/12), `forger_pick` (copy a hex's production — candidates come from `gainsFromHex`, so the forger sees through the robber; only entered with ≥2 candidates). A roll triggering both chains nests as `forger_pick(resume = curio_pick(resume = main))`.
- **The forger token moves only when its forger moves it** — seeded onto the desert by `handlePickBonus`, never relocated by a 7. The move is compulsory and gates the roll (`mustMoveForgerToken`). A legacy forger with no `forgerToken` resolves through `forgerTokenHex(p, state.robber)`.
- **Set-3 sub-phase** — `magician_pick`: opens after the magician's own roll fully resolves, wraps outermost so its phantom production doesn't affect its inputs (`wrapMagicianWindow` at the 7-chain transitions). Magician and fortune_teller are mutually exclusive by roller bonus.

### Two rules for sub-phase overlays

Both exist so the board stays reachable. Break either and a player stares at a sheet they can't get past.

1. **Only the acting player gets a modal.** Everyone else gets a plain top status line in `lib/game/TopArea.tsx` — a waiting player has no decision, so covering their board buys nothing. There is deliberately no `*WaitOverlay` component; write a status line instead.
2. **A modal whose choice depends on the board must be minimizable** — use `MinimizableModal` (see `lib/modules/CLAUDE.md`). `MagicianPickOverlay`, `SpecialistDeclareOverlay`, `ForgerPickOverlay`, `AccountantPicker`, and `ScoutPickOverlay` qualify (they name board positions the player must look at). Board-independent picks (resources, ratios) use a plain `Modal`. The forger's own token move is the counter-example: it's not a modal at all but a board pulse + `ConfirmBar`, because a compulsory choice entirely about board position has no business behind a sheet.

### Set-3 non-phase mechanics and special build

- **Non-phase mechanics are inline**: plutocrat (+50% summed roll gain — but note `applyRollOutcome` applies `plutocratGain` itself after summing `distributeResourcesByHex`, so a new server-side production path must do the same or plutocrat silently stops), smith (brick/ore cost swap), merchant (a ratio-1 rate in `bankPartitionFor`, not a payload), fencer (reserved edges in `GameState.fenceTokens`), investor (trios in `PlayerState.investments`, paid on roll resolve; uncapped, and shown everywhere as `InvestmentTokens` — one resource-colored dot per token, never a count out of a maximum), haunt (`'ghost'` buildings worth 0 VP, transparent to distance/longest-road via `isGhost`; a seat's _unspawned_ spots render only for that seat, which is why `BoardView` takes a `viewerIdx`).
- **`special_build`** (5–6p, `config.extraBuild`) sits between an `end_turn` and the next `roll`. `queue[0]` is the acting builder (NOT `current_turn`); they may build or buy a dev card — **nothing else. Trading of any kind is main-turn only** (bank trades here caused a lockout: trading down mid-slot dropped the builder under `moreThanSeven`, disabling the build they entered for). Gated by `isSpecialBuildActor`. Fully mirrored in the edge function.
- **`placedTurn`** (on occupied vertices/edges) records `state.round` at placement; initial pieces stamp `0`. Used by the accountant's liquidation gate ("not the same turn it was bought").

Run the `dev/check-catan-*.ts` scripts after editing the corresponding rules file; the edge function is only validated at deploy time (`npm run edge`).

## Spectating

A game whose `config.spectators` is true is readable by anyone friends with at least one player (additive RLS policies on `games`/`game_states`/`game_messages`). Full design in `.claude/specs/spectating.md`; the parts that matter here:

- **`isSpectator` comes from `useGame()`, never a local `participants.includes` check** (one derivation).
- **The spectator view is the same components with props gated, not a forked tree.** `meIdx` is `-1`, which already makes every seat-keyed overlay and board interaction inert; the explicit `!isSpectator` gates make the intent legible. Forking would guarantee drift.
- **A spectator gets no bottom bars**, so `spectatorStatus()` in `TopArea.tsx` must name the actor for _every_ phase — an exhaustive `switch`, so a new phase fails to compile.
- **Chat is two-way** — `handleSendMessage` authorizes spectators via `isGameSpectator`, a service-role mirror of the RLS predicate (keep the two in step). The `watching` tag on a message is derived, not stored.
- **"May watch" ≠ "is watching".** `spectatableGames` (the store) is every readable game; the header tab strip shows only `profiles.spectating`, the games actively opened. `useSwitchableGames` intersects the two.

## Sparse storage

`GameState.vertices`/`edges` are `Partial<Record<…>>`; missing keys default to `{ occupied: false }` via `vertexStateOf`/`edgeStateOf`. Write only occupied entries — never pre-fill the 54 + 72 empty ones.
