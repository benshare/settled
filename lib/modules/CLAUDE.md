# Modules

Shared, app-agnostic UI primitives (not Catan-specific). Style with `StyleSheet.create`, usually via a `makeStyles(colors)` factory memoized against `useTheme()`.

- `Modal.tsx` — **base overlay primitive; the only way to render a modal.** Wraps React Native's `<Modal transparent animationType="fade">` and bakes in the dismissal behavior every overlay needs: a dimmed backdrop that closes on outside tap and `onRequestClose` (Android hardware-back / web Escape) routed to `onDismiss`. The dismiss target is an `absoluteFill` `Pressable` rendered **behind** the content, not a wrapper around it (same pattern as `ChatPanel`) — a Pressable ancestor claims the touch responder on press-in and starves any `ScrollView` inside the sheet of its drag gesture, so a scrollable modal body silently stops scrolling. As a sibling it can't, and taps on the content never reach it anyway. Content-agnostic — callers pass their own sheet as `children` and style it via `contentStyle`; the component itself only contributes a default corner radius + soft shadow (both overridable). Props: `visible`, `onDismiss?`, `dismissOnBackdropPress?` (default `true`), `children`, `contentStyle?`, `backdropStyle?`, `layout?` (a reanimated layout transition for the content wrapper — e.g. `LinearTransition` so the sheet resizes smoothly as its content grows/shrinks). Set `dismissOnBackdropPress={false}` for forced-choice / terminal overlays that must not close on an outside tap (they can still omit `onDismiss` to also trap hardware-back/Escape, or pass one to allow it). Do NOT hand-roll a raw `<Modal>` + backdrop `Pressable` again — use this so dismissal stays uniform.
- `MinimizableModal.tsx` — a `Modal` whose body collapses to just its title bar, via a chevron in the title row. **Top-anchored** (its backdrop uses `justifyContent: 'flex-start'` + `paddingTop: insets.top`) rather than centered — that's what makes minimizing useful, since the header holds position and the sheet shrinks upward instead of re-centering. Owns the sheet chrome (background, padding, radius, `gap`) and the title style, so callers pass only sizing overrides via `contentStyle` (e.g. `maxWidth`/`maxHeight`) and their body as `children`. Props: `title`, `visible?` (default `true` — callers normally mount conditionally), `onDismiss?`, `dismissOnBackdropPress?`, `contentStyle?`, `children`. Use this instead of `Modal` whenever the choice being asked for depends on what's behind the overlay — the alternative is a player who must dismiss and reopen to see what they're deciding about. A plain centered `Modal` stays correct when the sheet already contains everything needed.
- `ConfirmModal.tsx` — styled replacement for the native `confirm()` dialog (title/message/confirm/cancel, `destructive`, `submitting`, `error`). Built on `Modal`. Use for any "are you sure" before a destructive or irreversible action.
- `SlidingArea.tsx` — horizontal slide between a fixed set of children selected by `index`. Shows the child at `index`; when `index` changes (consecutively or by a jump) the previous pane slides out and the new one slides in, direction taken from the sign of the delta (higher index enters from the right). Non-consecutive jumps slide the two panes **directly** past each other — it does not scroll through the intermediate ones. **Keep-alive**: every pane stays mounted for the area's lifetime, so each child keeps its own state across switches (unlike `catan/GameSwitchTransition.tsx`, which swaps state under one shared tree). The active pane is laid out in flow so it drives the area's height and carries a `zIndex` so the incoming pane wins the crossing; every other pane is absolutely positioned and hidden (`opacity: 0`, `pointerEvents: none`) — still mounted and measured, so it's ready the instant it's selected — with the one currently sliding out getting the outgoing transform instead. `overflow: 'hidden'` clips the travelling panes to the area's edges. Width is **measured** via `onLayout` (not the window), and the first transition is gated until it's known — a change before layout snaps without animating. Props: `index`, `children`, `duration?` (ms, default 360), `style?`. Panes that render multiple siblings must supply their own spacing (e.g. a wrapper with `gap`), since the area adds none. Used by the Stats screen's tab body.
- `Button.tsx`, `Input.tsx`, `Avatar.tsx`, `Tooltip.tsx`, `TabBarIcon.tsx` — the rest of the shared primitives.

## Overlays

Every modal/dialog/panel overlay renders through `Modal.tsx`. The one intentional exception is `lib/catan/GameChat.tsx`'s `ChatPanel`, which is an absolutely-positioned in-play-area view (NOT an RN `<Modal>`) so it stays inside the board rather than covering the screen — see `lib/catan/CLAUDE.md`. The three Catan animation overlays (`StealAnimation`, `NomadAnimation`, `FortuneTellerAnimation`) keep a raw RN `<Modal>` because their backdrop is an `Animated.View` driven by a custom fade timeline and they are transient + non-dismissible — not the dialog pattern `Modal` targets.

### Stacking

Anything rendered through `Modal.tsx` is already above everything else: RN's `<Modal>` gets its own layer (a native window; a `document.body` portal at `z-index: 9999` on web), so it never competes with the screen's own views and needs no `zIndex` of its own. The in-tree overlays do compete, and they order themselves with the `z` scale in `lib/theme.ts` — `playArea` < `floatingButton` < `panel` < `chat`. Use those tokens rather than a bare number; the bug they fix (an expanded panel painting under a floating button that shares its `zIndex`, or under the top/bottom bars it's supposed to overhang) is invisible until the two happen to overlap. Two non-obvious pieces of the scale: the game screen's board container carries `z.playArea` **only** so the panels floating inside it can overhang the player strip and the action bars, which are its siblings — and consequently anything else mounted at the play-area root that sits over the board (the chat scrim, `FinalScoreButton`) must carry a token above it.
